# 開発のおおまかな流れ

1. 目的・機能候補・優先順位を決める  
   アプリで達成したいこと、将来を含めた機能候補、最初に作る範囲を整理する。

2. 最初の完成版の仕様を固める  
   記録項目、入力方法、集計ルール、公開範囲などを決める。

3. 画面仕様と操作フローを決める  
   ログイン、記録、グラフ、追加・編集の画面と操作の流れを決める。

4. ワイヤーフレームでモックアップを作り、操作フローを確認する
   見た目のデザインは決めず、画面要素の配置と遷移を確認する。想定した操作を一通り行い、入口・戻り先・操作漏れを見つけて仕様へ反映する。

5. 最初の完成版の受け入れテスト項目を作る
   技術に依存しない、利用者の操作と期待する結果をテスト項目として整理する。技術構成を選んだ後に、実装向けのテスト方針を追加する。

6. 技術構成と公開方法を選ぶ
   認証サービス、データベース、ホスティングなどを決める。

7. 画面デザインを作る
   ワイヤーフレームを基に、色、余白、文字サイズ、グラフの見た目、演出、端末ごとの配置を決める。

8. 画面デザインの受け入れテスト項目を作る
   画面デザインが決まった後に、端末ごとのレイアウト、見切れ、文字の読みやすさ、操作要素の大きさなどの確認観点を整理する。実際のテスト前に、対象環境ごとに展開し、各判定IDへ `OK` または `NG` を記録できる粒度へ具体化する。

9. 開発基盤を作り、実装する
   実装時の確認メモを見直し、次の順番で進める。

   1. React、TypeScript、Viteのプロジェクトを作り、npm、React Router、Vitest、ESLint、Prettierを設定する。仮のページをCloudflare Pagesで表示できるところまで確認する。
   2. PCやVS Codeで編集・確認できるタイミングでGitHub Actionsを設定し、push後に整形、コード検査、自動テスト、ビルドを自動確認できるようにする。VS Codeでの作業を再開したときは、この設定を未実施なら先にリマインドする。
   3. 配色、文字、ボタン、アイコン、右上メニュー、下部タブなどの共通UIを作る。
   4. Supabaseへ接続せず、仮データを使って記録画面、グラフ画面、年月選択、睡眠一覧、追加・編集、削除確認、ログイン画面、プライバシーポリシーを作る。
   5. 仮データの状態で一連の画面操作とレスポンシブ表示を確認し、画面仕様とデザインを調整する。
   6. Supabase Auth、PostgreSQL、RLSへ接続し、認証、睡眠記録の取得・保存、追加・編集・削除、重複禁止、複数端末での同期を実装する。
   7. AWS SESをSupabase Authのメール送信先として設定し、ワンタイムコードによるログインを確認する。
   8. Cloudflare Pagesに環境変数を設定し、公開環境で動作を確認する。
   9. 機能とデザインのテスト項目を実施可能な形式へ具体化し、最終テストを行う。

10. 実際に使い、必要な機能だけ追加する
   数日〜数週間使い、不便な点や必要性が確認できた機能を追加する。
