# v0 受け入れテスト項目

## 目的と範囲

最初の完成版が、利用者の操作として [specification.md](specification.md) の仕様どおりに使えるかを確認する。

- 各判定IDに対して、テスト実施時に OK または NG を記録する。
- デザイン上の細部は、画面デザインの決定後に別途確認する。
- 通信失敗、単体テスト、セキュリティ診断などの実装向けテストは、技術構成を選んだ後に追加する。

## 前提データ

- 日付をまたぐ睡眠
- 月をまたぐ睡眠
- 1日に複数回の睡眠
- 16:00の表示区切りをまたぐ睡眠
- 16:00より前に始まり、翌日16:00より後に終わる睡眠
- 睡眠記録がない日
- 起床日時が未入力の睡眠記録

## 後続テスト作成時のメモ

次の内容は、この文書の機能テストとは分けて、画面デザインまたは実装方法が決まった後に判定ID付きのテスト項目として具体化する。

### 画面デザインの受け入れテスト

- `[ログイン画面]` 長いメールアドレスを表示しても、入力欄やコード送信結果のメッセージからはみ出さず、必要に応じて折り返される。
- `[ログイン画面]` ソフトウェアキーボードを表示しても、認証コード入力欄とログインボタンを確認・操作でき、必要に応じて画面をスクロールできる。
- `[全画面]` 狭い画面や文字サイズを拡大した状態でも、文言や操作要素が見切れたり重なったりしない。
- `[全画面]` 有効な操作と無効な操作を、色の違いだけに頼らず判別できる。

### 実装向けテスト

- `[ログイン画面]` iPhoneのSafariで、メールで受け取った認証コードの自動入力を利用できる。
- `[ログイン画面]` 先頭が `0` の認証コードを含め、6桁をまとめて貼り付けられる。
- `[ログイン画面]` 対応する端末で認証コード入力欄に数字キーボードが表示される。
- `[ログイン画面]` コード送信、コード再送、ログインの通信中に、同じ操作が重複して実行されない。
