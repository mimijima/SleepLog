# v0 実装時の確認メモ

## 位置づけ

この文書には、仕様・画面デザインの検討中に出た、実装開始時または実装中に改めて確認する事項を記録する。

-   確定した利用者向け仕様は、[specification.md](specification.md) を参照する。
-   採用した画面デザインと視覚素材の方針は、[../../design/visual-directions/README.md](../../design/visual-directions/README.md) を参照する。
-   採用するサービスと未決定の運用事項は、[tech-selection.md](tech-selection.md) を参照する。
-   この文書のコード例や実装案は、使用するフレームワークの決定後に再確認する。正式仕様と矛盾する場合は、正式仕様を優先する。

## 認証コード入力

-   認証コードは、6 桁をまとめて入力・貼り付けできる 1 つの入力欄として実装する。
-   先頭が `0` のコードを保持できるよう、数値型の入力欄としては扱わない。
-   HTMLでは、`type="text"`、`inputmode="numeric"`、`autocomplete="one-time-code"`、`maxlength="6"` などの使用を検討する。
-   iPhoneのSafariで、数字キーボード、コードの貼り付け、認証コードの自動入力を実機確認する。
-   Androidでは同じ標準HTML属性を使用し、対応する端末・ブラウザでは自動入力を利用できるようにする。自動入力できない環境でも、数字キーボードと貼り付けを利用できることを確認する。

## 睡眠日時の入力

-   追加・編集入力の就寝日時入力欄と起床日時入力欄は、それぞれ日付欄と時刻欄に分ける。
-   日付欄には標準の HTML `input type="date"`、時刻欄には標準の HTML `input type="time"` を使用し、端末・ブラウザが提供する日付・時刻ピッカーで入力できるようにする。
-   ピッカーの見た目はOS・ブラウザごとに異なるため、独自のカレンダーや時刻選択UIはv0では作らない。
-   追加状態の空欄には、独自のハイフンや案内文字を入力欄の上へ重ねない。端末標準の空欄表示を使い、位置ずれや標準UIとの重なりを避ける。
-   iPhoneのSafariで日付・時刻の選択、Androidの対応端末またはエミュレーターで入力欄と標準ピッカーの基本動作を確認する。実機の標準ピッカーの最終確認は、利用する端末で行う。

## ログイン画面のメッセージ

-   初回のコード送信前は、コード送信結果のメッセージ領域を表示しない。
-   初回のコード送信後、コード再送後、ログイン失敗後は、同じメッセージ要素を再利用して内容と表示状態を切り替える。
-   メッセージ領域は固定の高さにせず、想定する最長の文言、狭い画面、文字サイズを拡大した状態で通常のメッセージが収まる `min-height` を設定する。さらに長い文言は自然に折り返して領域を広げ、途中で切らない。
-   成功・再送・失敗は色だけで区別せず、文言でも状態が分かるようにする。
-   ログインに失敗しても、入力済みの認証コードは消去せずに残す。
-   メッセージの確定文言は、ログイン画面の実装前に決める。

## ログイン画面の通信処理中表示

-   コード送信、コード再送、ログインの通信中は、同じ操作を連続して実行できないよう、対象の操作を一時的に無効にする。
-   通信中であることを文言、進捗表示、ボタンの状態などのどの方法で伝えるかは未決定とし、ログイン画面の実装前に決める。
-   通信中の表示へ切り替えても入力欄や周囲の要素が大きく動かないようにする。
-   通信が完了したら結果に応じた状態へ切り替え、失敗時は共通のメッセージ領域へログイン失敗メッセージを表示する。

## 視覚素材と画面表現

-   実装用の部屋背景とロールカーテン素材を用意する際は、同じ元絵を基にして縮尺、配置、線の太さ、塗りの質感を揃える。
-   検討用に生成した背景画像をそのまま使うか、元画像から必要な部分を切り抜くか、新たに実装用素材を作るかは、実装開始時に画像を確認しながら相談する。
-   背景、動くロールカーテン、明暗・光のレイヤー、文字、操作要素の重なり順を実装前に整理する。
-   SVGアイコン、就寝ボタンの手描き風の縁取り、CSSによる明暗・文字色・影の変化は、デザインREADMEの実装方針を参照して作る。

## グラフとレスポンシブ表示

-   グラフの1日分の行は、同じ表示条件ではすべて同じ高さに揃える。
-   棒、目盛線、曜日色などはHTML・CSS・SVGで描画し、端末幅に応じて調整できるようにする。
-   画面幅と縦横比を変えながら、1画面に見える日数、時刻の数値を表示する間隔、余白、文字の読みやすさ、操作要素の大きさを確認する。
-   iPhone 15向けのデザイン画像は基準の1つとし、他のスマホ・タブレット・PCで同じ機能と操作フローを保てることを確認する。
-   初期表示では、数日前を上端側に置き、現在時刻を含むグラフ行より下の残りを未来の空行で埋める。未来の空行数は固定せず、端末の表示領域と1行の高さから決める。
-   現在時刻を含むグラフ行は、設定された表示区切り時刻を使って判定する。
-   初期位置、未来の空行数、未来行の操作可否は、睡眠データの取得・集計とは分離した表示ロジックとして実装する。実際に使用した結果、現在時刻を含むグラフ行を画面下端に変更する場合も、DB構造や集計処理を変更せずに調整できるようにする。
-   年月選択で選べる年の下限は、年月選択処理へ直接埋め込まず設定値として管理する。v0 の設定値は 2016 年とし、後から画面やデータ構造を変更せずに調整できるようにする。

## 睡眠記録の重複防止

-   追加・編集画面では、保存前に既存の睡眠記録との重複を確認し、利用者が修正しやすいメッセージを表示する。
-   複数端末からの同時保存でも重複を防げるよう、画面側の確認だけに依存せず、Supabase PostgreSQLにも利用者単位の排他制約を設定する。
-   PostgreSQLの範囲型とGiST排他制約を使い、時間範囲は起床日時を含まない半開区間 `[)` として扱う。これにより、前の記録の起床日時と次の記録の就寝日時が同じ場合は保存できる。
-   利用者IDと時間範囲を組み合わせた排他制約には、Supabaseで利用できる `btree_gist` 拡張を使用する。実際のSQLと列名はデータベース設計時に確定する。
-   データベースの排他制約によって保存が拒否された場合も、画面では「他の睡眠記録と時間が重なっています」と表示し、入力値を残す。

## 睡眠日時の入力エラー表示

-   入力エラーは、起床日時入力欄の後、保存・キャンセルボタンの前に表示する。
-   第一候補は、枠で囲まず、エラーアイコンと本文を横並びにする表示とする。本文は1行または2行に自然に折り返し、読みやすい文字サイズを保つ。
-   エラー文言には文末の「。」を付けない。
-   表示文言は次のとおりとする。未入力は追加・編集のどちらでも確認する。
    -   未入力：`就寝日時と起床日時を入力してください`
    -   起床日時が就寝日時以前：`起床日時は就寝日時より後にしてください`
    -   未来日時：`未来の日時は記録できません`
    -   重複：`他の睡眠記録と時間が重なっています`

## 追加・編集入力の保存中・通信失敗時の表示

-   保存中のボタン表示・入力欄の扱いと、通信失敗時の表示文言・見た目は未決定とする。保存ボタンを無効にする利用者向け仕様を満たしつつ、実装時に画面デザインとあわせて決める。

## サービス停止時の扱い

-   Supabase無料プランのプロジェクトが一時停止した場合のアプリ上の表示と、管理者による再開手順は未決定である。
-   実装時には、通常の通信エラーとサービス停止を画面上で区別できるかを確認し、利用者へ表示する内容と管理者の再開手順を決める。
-   この項目の元の未決定事項は、[tech-selection.mdの「採用構成で後から決めること」](tech-selection.md#採用構成で後から決めること) を参照する。
