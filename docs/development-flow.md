# 開発のおおまかな流れ

1. 目的・機能候補・優先順位を決める  
   アプリで達成したいこと、将来を含めた機能候補、最初に作る範囲を整理する。

2. 最初の完成版の仕様を固める  
   記録項目、入力方法、集計ルール、公開範囲などを決める。

3. 画面仕様と操作フローを決める  
   ログイン、記録、グラフ、追加・編集の画面と操作の流れを決める。

4. ワイヤーフレームでモックアップを作り、操作フローを確認する
   見た目のデザインは決めず、画面要素の配置と遷移を確認する。想定した操作を一通り行い、入口・戻り先・操作漏れを見つけて仕様へ反映する。

5. 最初の完成版の受け入れテスト項目を作る
   技術に依存しない、利用者の操作と期待する結果をテスト項目として整理する。技術構成を選んだ後に、実装向けのテスト方針を追加する。

6. 技術構成と公開方法を選ぶ
   認証サービス、データベース、ホスティングなどを決める。

7. 画面デザインを作る
   ワイヤーフレームを基に、色、余白、文字サイズ、グラフの見た目、演出、端末ごとの配置を決める。

8. 実装の順番を決めて開発する
   最初の完成版に必要な機能から実装する。

9. 実際に使い、必要な機能だけ追加する
   数日〜数週間使い、不便な点や必要性が確認できた機能を追加する。
